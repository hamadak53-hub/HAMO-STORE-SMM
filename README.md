# HAMO STORE SMM

متجر عربي مستقل لخدمات السوشيال ميديا.

## الملفات الأساسية
- `index.html` و`style.css` و`script.js`: واجهة العملاء.
- `main.py`: API الحسابات والخدمات والطلبات ولوحة الإدارة.
- `admin.html` و`admin.css` و`admin.js`: لوحة تحكم الإدارة.
- `render.yaml`: إعداد نشر Render Blueprint.
- `requirements.txt`: مكتبات Python.

## تشغيل محلي
```bash
pip install -r requirements.txt
```
على Windows PowerShell:
```powershell
$env:SECRET_KEY="ضع-قيمة-عشوائية-طويلة"
$env:ADMIN_USERNAME="admin"
$env:ADMIN_PASSWORD="كلمة-مرور-قوية"
uvicorn main:app --reload
```
افتح `http://127.0.0.1:8000`، ولوحة الإدارة من `/admin`.

## النشر على Render
استخدم Blueprint من ملف `render.yaml` أو أنشئ Web Service:
- Build: `pip install -r requirements.txt`
- Start: `uvicorn main:app --host 0.0.0.0 --port $PORT`

اضبط المتغيرات السرية:
- `SECRET_KEY`: مفتاح عشوائي طويل وسري.
- `ADMIN_USERNAME`: اسم دخول الإدارة الذي تختاره.
- `ADMIN_PASSWORD`: كلمة مرور قوية تختارها.
- `DATABASE_URL`: رابط PostgreSQL دائم (موصى به للإنتاج).\n- `PANELFOLLOWS_API_KEY`: مفتاح API من حساب PanelFollows؛ يُحفظ في Render Environment فقط ولا يوضع في GitHub.
- `COOKIE_SECURE=true` عند استخدام HTTPS.

لا تضع كلمات المرور أو مفاتيح المورد داخل ملفات GitHub.

## الموجود حاليًا
- إنشاء حساب عميل وتسجيل الدخول.
- إضافة خدمات وتحديد سعر كل 1000 وحدة والحد الأدنى والأقصى.
- إرسال طلب خدمة بعد تسجيل الدخول.
- متابعة حالة الطلب من لوحة الإدارة وتحديثها.
- محفظة مستقلة لكل عميل وسجل مالي للحركات.
- طلبات شحن يدوية عبر فودافون كاش وإنستاباي والتحويل البنكي، مع اعتماد الإدارة قبل إضافة الرصيد.
- خصم تكلفة الطلب من المحفظة عند إنشائه.
- رد المبلغ للمحفظة عند رفض أو إلغاء طلب سبق خصم قيمته، مع منع تكرار الاسترداد.
- مراجعة طلبات الشحن من لوحة الإدارة.
- إخفاء الخدمات بدل حذفها.

## ملاحظات مهمة
- الأسعار التي تدخلها هي **سعر كل 1000 وحدة بالجنيه المصري**؛ قيمة الطلب تُحسب تلقائيًا حسب الكمية.
- شحن الرصيد يدوي في المرحلة الأولى؛ لا يوجد تكامل دفع إلكتروني أو تأكيد تلقائي.
- يجب على الإدارة التحقق من وصول التحويل فعليًا قبل الموافقة على طلب الشحن.
- طلب الخدمة يخصم رصيده فور إنشائه، وتبدأ حالته "تم الدفع" لتتابع الإدارة التنفيذ يدويًا.
- تكامل PanelFollows API v2 على فرع الاختبار: فحص رصيد المورد، تحميل خدمات TikTok، استيراد الخدمة بسعر بيع محلي بالجنيه، وإرسال الطلب تلقائيًا عند ربط الخدمة.\n- متابعة حالة طلب المورد متاحة من endpoint الإدارة `/api/admin/provider/orders/{local_order_id}/sync`.\n- الخدمات المستوردة تبدأ مخفية، ويجب مراجعة السعر والحدود وتفعيلها يدويًا.\n- عند رفض المورد الطلب أثناء الإرسال، يُرفض الطلب المحلي ويُرد المبلغ للمحفظة.\n- لا يوجد مزامنة دورية تلقائية لحالات المورد؛ تتم المزامنة من endpoint الإدارة.
- صفحة المحفظة: `/wallet`، ولوحة الإدارة: `/admin`.
- استخدم PostgreSQL في Render؛ قاعدة SQLite المحلية ليست مناسبة لاستضافة مؤقتة قد تمسح الملفات عند إعادة النشر.
